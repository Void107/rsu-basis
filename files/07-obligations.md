# 07 — 按触发条件分级的义务清单

> **本文档不是法律意见。** 作者不是律师。这是一份工程与产品视角的义务清单，用于把问题结构化，便于在需要时与律师沟通。每一项在实施前都需要执业律师确认适用性。

本文档的组织方式是**按触发条件**而不是按法规。原因：内部试用阶段绝大多数义务并未激活，但只要越过某条线就会一次性激活一批。把线画清楚，比列一堆当前用不上的法规更有用。

---

## 1. 现在就必须处理：IP 归属

**这是唯一一件事后无法补救的事，也是唯一在内部试用阶段风险反而更高的事。**

直觉是「内部试用更安全」。实际相反：内部试用把项目和雇主的 IP 主张深度绑定。

你的雇佣协议里几乎肯定有发明转让条款。加州 Labor Code §2870 划了界限——完全用自己的时间、不使用雇主设备/设施/商业秘密、且与雇主业务或其实际及可预见的研发无关、亦非源于你的工作职责的发明，不予转让。

风险点在「与雇主业务相关」这一条。你在做表格产品，然后做一个 AI 表格工具，这个论证并不轻松。而以下每一项都在削弱 §2870 的豁免要件：

- 用公司设备开发或运行
- 在公司时间开发
- 在内部渠道（Slack、邮件列表）分发
- 邀请同事参与测试
- 使用任何公司内部资源或信息

**在引入任何同事之前先取得书面结论。** 三种结果对应不同后续，见 `README.md` P-1。

这一条本文档无法替你判断——需要你自己读雇佣协议，必要时咨询律师。**它是四条纪律里唯一有时间窗口的。**

## 2. 内部试用阶段实际激活的义务

假设 P-1 已经解决。这个阶段真正要守的只有四条：

### 2.1 不接触任何人的文档

三条独立理由，任何一条都足够（详见 `docs/06` §2）：公司数据政策、州泄露通知法、去标识不可靠。

**架构上保证而不是纪律上保证**：应用是单文件 HTML、零出网、零持久化，同事的文档在物理上到不了你手里。这也是为什么 `CLAUDE.md` R8 不能推迟。

### 2.2 零出网、零持久化

`CLAUDE.md` R8。现在做是免费的，等有了几千行代码再回头改是重构。

它同时让 2.1 自动成立。

### 2.3 免责与不变量

**在内部试用阶段比对外发布时更重要，不是更不重要。**

对外发布时用户是陌生人，出错是产品问题。内部试用时同事拿你的输出去报税，算错了他收 IRS 通知、补税加罚息——**这是你和同事之间的事，没有公司实体挡在中间。**

所以：
- `docs/02` §4 的 7 条不变量一条不放松，尤其是 I5（调整方向只能为负）
- `docs/05` §6 的定位文案照常执行
- 每次分发都附书面免责，明确要求交 CPA 复核（`docs/08` §3）

### 2.4 设备安全基线

你自己的开发机上有你自己的 W-2 和券商文档，以及 golden set。基线要求：

- 全盘加密（FileVault / BitLocker）
- 屏幕锁定
- 仓库中的 golden 文档若含真实数值，仓库不得公开
- 备份也要加密

## 3. 内部试用阶段可以推迟的

以下在「免费、不收集文档、不出网、不公开」的前提下均未激活：

| 义务 | 为什么现在不适用 |
|---|---|
| IRC §7216 同意架构 | preparer 认定通常挂在「从事该业务」或「获得报酬」，免费内部工具两头够不上 |
| GLBA / FTC Safeguards、WISP | 需要有 customer |
| 州级综合隐私法 | 需要有 consumer / 达到适用门槛 |
| 隐私政策、ToS、GLBA 通知 | 无对外服务 |
| DPA、子处理方清单 | 无子处理方 |
| 事故响应计划、渗透测试、SOC 2 | 无服务端、无留存 |
| 保险 | 见 §6 的例外说明 |

**但这不等于「不用了解」。** §4 的触发表决定了它们什么时候回来。

### 3.1 由此产生的一个产品决定

**内部试用版不做 LLM 回退（`docs/03` 的 L3）。**

理由：向第三方传输文档内容是 §7216 意义上的披露，而有效同意需要 Rev. Proc. 2013-14 规定的独立文件格式——为一个内部工具做这套不划算。

砍掉 L3 的收益不只是省事：整个产品在架构上根本没有出网路径，「断网也能跑」变成无条件成立而不是有例外。代价是新券商版式的冷启动变慢，但内部阶段本来就只覆盖少数几家，且有 `docs/06` §3 的结构描述表作为替代手段。

`docs/03` 中 L3 的规格保留，但标记为「对外分支才实现」。

## 4. 触发表

每一行是一条线。越过就激活右列，且**通常是一次性激活一批**。

| 触发条件 | 激活的义务 |
|---|---|
| 引入任何同事参与 | IP 归属结论（§1）；书面免责；不收集文档的纪律 |
| **你接触了任何他人的文档**（哪怕一份、哪怕对方主动发的） | 公司数据处理政策；州数据泄露通知法（SSN 触发全部 50 州）；设备加密与销毁流程 |
| **开始收费**（任何形式） | IRC §7216（preparer 认定几乎确定）；FTC Safeguards Rule；隐私政策；ToS；PCI（用托管字段可降至 SAQ A） |
| **公开可注册**（免费也算） | 州级综合隐私法（截至 2026 年 8 月已有 20 部生效，门槛差异大）；FTC Act §5（隐私主张必须真实）；隐私政策；州级权利请求处理；GPC 信号响应 |
| **任何文档内容出网** | §7216 书面同意（Rev. Proc. 2013-14 规定格式：独立文件、规定开头语、载明接收方与用途、且必须写明「不签也能用」）；子处理方 DPA |
| **服务端存储任何用户数据** | Safeguards Rule 全量：WISP、Qualified Individual、加密、MFA、日志、事故响应、供应商监督、年度报告；泄露通知（FTC 30 日 / 500 人以上） |
| **CPA 复核他人文档** | §7216 披露同意；与该 CPA 的书面协议 |
| **用他人数据构建 golden set 或改进产品** | §7216「使用」同意 |
| 达到州法营收/人数门槛 | CPRA 风险评估与网络安全审计；数据经纪商登记（如适用） |

### 4.1 最容易被无意越过的两条

**「你接触了任何他人的文档」。** 同事出于好意直接把 PDF 发到你的 Slack —— 这一刻线就越过了。

预防：在分发说明里明确写「请不要把文档发给我，我收到会立即删除并告知你」。收到后照做，并留一条记录。

**「公开可注册」。** 把单文件 HTML 传到一个公开的 GitHub Release 或个人网站，就已经不是内部试用了。

预防：内部阶段的分发只走点对点（`docs/08` §2）。

## 5. 若决定对外：工作量预估

这不是补充几份文档的事。粗略量级：

| 项 | 说明 |
|---|---|
| §7216 适用性法律意见 | **最先做**，因为结论会反过来影响架构 |
| §7216 同意书 + UI 流程 | 若保留任何出网路径 |
| 隐私政策 / ToS / GLBA 通知 | |
| CSP、零第三方脚本、供应链策略的工程落地 | 内部阶段已做，这部分是白赚的 |
| 可复现构建 + 公布 bundle 哈希 | 让 local-first 可被第三方验证 |
| 账号与支付系统（与文档系统物理隔离） | |
| WISP、事故响应、DPA、州级权利请求流程 | |
| E&O / 技术专业责任险 + 网络安全险 | |
| SOC 2 Type II（若走 CPA 渠道） | |

合计与 P0–P5 是同一个量级。**这就是为什么对外发布必须是显式决策，而不是默认路径。**

---

## 6. 一个不受阶段影响的建议

即使只在内部试用，也值得了解一下个人责任险（E&O / 技术专业责任险）的成本。

不是因为法律要求，而是因为 §2.3 那个现实：同事拿你的输出去报税，中间没有公司实体。这个敞口在你收第一分钱之前就已经存在了。

具体是否需要、买什么额度，需要问保险经纪，不在本文档能判断的范围内。

---

## 7. 复查节奏

**每次扩大使用范围时重读 §4 的触发表。** 范围扩大通常是渐进的、无感的——多加几个人、换个分发方式、有人问「能不能收点钱」——而义务的激活是阶跃的。

在 `docs/08` 的试用运营检查表里，把「重读 §4」设为每次扩大范围的必经步骤。
