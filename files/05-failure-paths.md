# 05 — 失败路径

**先实现这份文档里的路径，再实现 happy path。**

理由：happy path 是最容易的部分，而这个产品的价值和风险全部在边缘。一个说「lot 7 的 vest 价我无法确定」的产品，比一个内插了合理数字的产品好得多。

每条路径给出：检测方式、阻断级别、用户看到什么、下一步是什么。

---

## 0. 阻断级别定义

| 级别 | 含义 | UI 行为 |
|---|---|---|
| **HARD** | 无法产出正确结果 | 停止，不生成 xlsx，给出具体的下一步 |
| **DECIDE** | 需要用户提供信息才能继续 | 暂停，展示候选，等用户裁决 |
| **WARN** | 可以继续但需要用户知情 | 继续，在 Summary 与 Checks 页标注 |

**没有「静默继续」这个级别。**

---

## 1. 文档层面

### F1 — 补充表整体缺失
**检测**：适配器 `locateSupplemental()` 返回 null
**级别**：HARD
**文案**：
> 我们在这份文件里没有找到成本基础补充表。正确的数字不在 1099-B 主表上，而在一份单独的补充信息表里，它通常在同一个 PDF 的后半部分（有时在第 50 页之后），标题类似 "Supplemental Information" 或 "Stock Plan Supplemental Information"。
>
> 如果这个 PDF 里确实没有，请到你的券商网站的 tax documents 区域单独下载它。
**下一步**：提供该券商的具体下载路径说明（适配器里维护）

### F2 — 扫描件，无文本层
**检测**：整页 `items.length === 0`
**级别**：HARD
**文案**：说明这是扫描版，需要从券商重新下载原生 PDF；提供路径。
**下一步**：不做 OCR。给手工补录入口作为备选。

### F3 — 检测到 CORRECTED 标记
**检测**：页眉/页脚含 "CORRECTED"
**级别**：DECIDE
**文案**：这份文件标记为更正版。券商通常在 2 月底到 3 月发出更正版 1099-B。请确认你使用的是最新的一份。
**下一步**：让用户确认或上传另一份；若已用旧版报过税，提示可能需要 1040-X（但不展开，V1 不做修正申报）

### F4 — 文档年度与所选税年不符
**检测**：文档内年份 ≠ 用户选择的税年
**级别**：HARD

## 2. 范围外情形（对应 `docs/01` §1）

这一组的共同处理：**明确告知这超出当前支持范围，不给出任何部分结果。**

部分结果在这个产品里比无结果更危险——用户会以为算完了。

| ID | 情形 | 检测方式 | 级别 |
|---|---|---|---|
| F5 | 混入 ESPP | 文档中出现 "ESPP" / "Employee Stock Purchase" 字样，或存在 purchase price ≠ 0 的批次 | HARD |
| F6 | 混入期权 | 出现 "ISO" / "NQSO" / "NSO" / "Exercise" | HARD |
| F7 | 卖出股数 > vest 总股数 | 引擎不变量 I2 | HARD |
| F8 | 多券商 | 用户上传了多个不同 `BrokerId` 的文件 | HARD（V1.1 支持） |
| F9 | 股票拆分 / 并购换股 | 文档中出现拆分比例，或 lot 股数出现非整数倍变化 | HARD |
| F10 | 跨年卖出（卖了往年 vest 的股，但只提供了当年文档） | 匹配时找不到对应 lot | DECIDE → 若用户有去年的 ledger xlsx 可上传则继续，否则 HARD |

F5 与 F6 的文案要给出正面的下一步，而不只是拒绝：
> 这份文件里包含 ESPP 交易。ESPP 的成本基础规则与 RSU 完全不同（涉及 qualified / disqualifying disposition 的判定），我们目前还不支持，算错的风险太高。
>
> 你可以：只上传只含 RSU 的部分；或者把这份底稿和 ESPP 部分一起交给 CPA 处理。
>
> [ 加入 ESPP 支持的等待列表 ]

那个等待列表按钮不是安慰，**它是你的 roadmap 优先级排序数据**。

## 3. 数据一致性

### F11 — 逐行合计 ≠ 文档印刷合计（校验 C1）
**级别**：HARD
**文案**：展示两个数字与差额，说明这通常意味着解析漏了行或多读了行。
**下一步**：提供手工补录界面，预填已解析的行，让用户对照原文档补齐。
**重要**：这是提取层最重要的安全网，**不允许提供「忽略并继续」选项**。

### F12 — 乘积不一致（校验 C2）
`sharesVested × vestFmv` 与独立提取的 `ordinaryIncome` 差额超容差。
**级别**：HARD
**可能原因**（文案里列出来，帮助用户自查）：Adjusted Cost 列是总额而非每股；FMV 口径不同；某一列读错了。

### F13 — W-2 锚定失败（校验 C5）
Σ ordinaryIncome 与 W-2 上的 RSU 合计对不上。
**级别**：DECIDE
**文案**：这通常意味着有一次 vest 没被包含在这份文件里，或者你的 W-2 里还有其他类型的股权收入。
**下一步**：若用户未提供 W-2，降级为 WARN 但在 Summary 页醒目标注「未做 W-2 对账」

### F14 — 长短期与券商标注不符（校验 C6）
**级别**：DECIDE
**文案**：券商标注的持有期与按 vest 日期计算的结果不同。券商也可能标错。展示两者与依据日期，让用户选。

### F15 — 股数不守恒（校验 C3）
**级别**：HARD

## 4. 匹配歧义

### F16 — 同日多 lot vest，sell-to-cover 无法唯一配对
**级别**：DECIDE
**文案**：这一天有 N 次 vest，代扣税卖出的股数无法唯一对应到其中一个。展示候选 lot（grant 编号、股数、FMV），让用户选。
**禁止**：不允许用「最接近」自动消歧。选错会导致 basis 用错 FMV。

### F17 — 一笔卖出跨多个 lot 且 term 不同
**级别**：正常路径，不是错误
**处理**：拆成多条 8949 行。在 Summary 页说明为什么一笔交易变成了多行。

### F18 — 1099-B 标注 specific identification 但未给 acquisition date
**级别**：DECIDE
**下一步**：让用户选择按 FIFO 处理，或手工指定 lot

## 5. 引擎不变量违反

### F19 — 调整方向为正（不变量 I5）
**级别**：HARD，且不可配置关闭
**文案**：
> 计算结果显示这笔调整会**增加**你的应税所得。这与 RSU 的机制不符——本工具的作用只可能是调高成本基础、降低应税所得。
>
> 出现这个结果说明数据或解析有问题。我们不会输出这个结果，因为按它报税可能导致少缴税、收到 IRS 通知并承担罚息。

**内部**：这条同时上报（脱敏后），因为它大概率是 bug 而不是数据问题。

### F20 — basis 总额超过 ordinary income 总额（不变量 I6）
**级别**：HARD

### F21 — 两次运行结果不一致（不变量 I7 / 校验 C7）
**级别**：HARD，`InvariantViolation`，上报
**文案**：对用户只说「内部校验未通过，我们不会输出可能有误的结果」，不展示技术细节。

## 6. 定位文案（贯穿全站）

以下表述在任何界面上都不允许出现：

| 禁止 | 原因 | 替代 |
|---|---|---|
| 「帮你报税」「自动报税」 | 暗示代客申报 | 「生成可交给会计师的底稿」 |
| 「你应该这样报」 | 构成税务建议 | 「按你提供的文档，调整后的成本基础是」 |
| 「我们保证准确」 | 不可承诺 | 「所有数字均可追溯到源文件，请与你的会计师复核」 |
| 「省税」「避税」 | 定性错误 | 「避免对已缴税收入重复缴税」 |
| 「已优化」「已修正你的报税」 | 暗示完成了申报 | 「已生成调整明细」 |

每个产出物的首屏与 xlsx 的 Summary 页顶部，必须有：

> 本工具生成的是工作底稿，不是税务申报表，不构成税务建议。请在提交申报前与持照税务专业人士复核。

## 7. 实现检查表

每条失败路径都要有：

- [ ] 一个自动化测试（构造触发它的 fixture）
- [ ] 一条明确的用户文案（不是 "Error: ..."）
- [ ] 一个具体的下一步（不是死路）
- [ ] 在自检报告中记录（只记 failure ID 与校验编号，不记任何数值）

第四项的用途：**失败路径的分布就是你的 roadmap。** 如果 F5（ESPP）在内部试用中占了 40%，V1.2 的优先级就确定了。

注意：内部试用阶段**没有服务端埋点**。数据来源是用户手动回传的自检报告（`docs/06` §4），完全自愿。这意味着样本有偏（愿意回传的人更投入），做优先级判断时要意识到这一点。
