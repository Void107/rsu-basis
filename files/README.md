# RSU Cost Basis Reconciler

一个 local-first 工具。拖入券商与工资文档，产出一份带公式、可追溯的 `.xlsx` 底稿，用于修正 Form 1099-B 上被低报的 RSU 成本基础。

**当前目标是公司内部试用，不是公开产品。** 这个定位决定了下面的阶段划分、分发方式和 golden set 方法。对外发布是一个需要显式决策才进入的分支，见 §「分支点」。

**产品不做的事**：不申报、不 e-file、不给税务建议、不签名。产出物是底稿和调整草稿。

---

## 核心架构判断

三条，任何改动都要先回到这里：

1. **LLM 只允许出现在「非结构化 → 结构化」这一层。** 所有算术由确定性代码完成。见 `CLAUDE.md`。
2. **文档不出设备，且这一点可被验证。** 内部试用阶段做成单文件自包含 HTML，同事本地打开、断网可跑。CSP 设 `connect-src 'none'`，浏览器强制执行。零持久化：不写 IndexedDB、不写 localStorage。
3. **缺数据就停，绝不内插。** 这个品类的错误是静默的、单向的。「算不出来」是可接受的输出，「自信地算错」不是。

第 2 条在内部试用阶段不只是隐私考虑，更是**让你在物理上无法接触同事的 W-2**。见 `docs/08`。

## 技术栈（已决策）

| 层 | 选型 | 理由 |
|---|---|---|
| 应用形态（内部） | **单文件自包含 HTML** | 零服务器、零上传、双击即用、断网可跑 |
| 应用形态（对外，若触发） | 同一份代码打包为静态站点 | 内部阶段不为此做额外工作 |
| 框架 | React 19 + TypeScript + Vite（`vite-plugin-singlefile`） | |
| PDF 解析 | `pdfjs-dist`（文本层） | 浏览器内运行，不出网 |
| 金额运算 | `decimal.js` | 禁止 `number` 做金额 |
| xlsx 生成 | `exceljs` | 支持活公式 + 样式 |
| 跨年状态 | xlsx 内隐藏 sheet | 不用浏览器存储 |
| 测试 | Vitest + `fast-check` | property test 是主要测试形态 |
| 后端 | **无** | 内部阶段不建任何服务端 |

单文件包会到 5–8 MB（pdfjs + exceljs 占大头）。可接受——它换来的是「这个文件里没有任何网络请求」这个可以当场验证的事实。

## 开发路径

七个阶段。每个 gate 不过就不进下一阶段。

### P-1 — IP 归属确认（在写任何代码之前）

**这是唯一一件事后无法补救的事。**

「在公司内部试用」不是降低风险，而是把项目和雇主的 IP 主张深度绑定。一旦用公司设备、公司时间、内部渠道分发、同事参与测试，加州 Labor Code §2870 的每一条豁免要件都在被削弱——尤其是「与雇主业务无关」那一条，考虑到你做的正是表格产品。

**Gate**：就归属取得书面结论。三种结果各自对应不同的后续：

| 结论 | 后续 |
|---|---|
| 公司拥有 | 按内部项目走，用公司资源没问题，但你个人不能带走 |
| 你个人拥有 | **不要用公司设备、不要在内部渠道分发**，内部试用改为个人邀请 |
| 共有 / 未定 | 停。在明确之前不要引入同事 |

`docs/07` §1 有更详细的说明。这一条不属于本文档能替你判断的范围——需要你自己读雇佣协议，必要时咨询律师。

### P0 — 数据可得性探测（3–5 天，不写产品代码）

只用**你自己的**文档。回答：补充表是不是机器可提取的？

- 文字层 PDF 还是扫描图？
- 表头列名的确切字符串？
- 有没有 per-lot 的 vest date / FMV / ordinary income reported？
- **有没有印刷合计行？**（后续所有交叉校验的锚点，没有它策略要重做）

原料清单与逐条检查见 `docs/09`。其中第 1 条（能否选中 PDF 里的文字）和第 4 条（有没有印刷合计行）是真正的 gate，其余可以将就。

**Gate**：至少 1 家券商（你自己用的那家）确认可提取全部必需字段，且有合计锚点。
**若未通过**：不要硬上 OCR，也不要去找同事要别家文档。P1 和 P3 完全不依赖真实文档（已有合成 case），先做那两层，把 P2 推后。见 `docs/09` §5。

> ⚠️ **若开发者本人不是美国纳税人**（无 1099-B / W-2），上述 gate 无法直接达成。改用 `docs/09` §7 的三段式 gate：数据存在性（自查）、版式可行性（公开样本）、真实世界验证（推迟到 P5）。可用的公开样本已整理在 `docs/11`，其中 Fidelity 的 Stock Plan Services 报税指南含全套样本表格。对冲手段见 `docs/09` §7.5。

### P1 — 确定性引擎 + golden set（2–3 周，CLI，无 UI）

先建 golden set，再写引擎。此阶段 golden 只来自两个来源：你自己的文档（手算验证）和合成构造。**不接收任何他人的文档**，理由见 `docs/06` §2。

`test/golden/synthetic-001` 与 `synthetic-002` 已就绪，推导过程见 `docs/10`。**开工前先按 `docs/10` 用纸笔把案例一算一遍**——它同时是对本规格的验证。

**Gate**：
- 7 条 property test 全过
- golden set 上 100% 匹配手算答案，金额零容差
- 至少 3 组是用纸笔完整算过的

### P2 — 提取层（3–4 周）

规则解析，单券商。**内部试用版不做 LLM 回退**——见 `docs/07` §3。

**Gate**：
- 目标券商上字段级准确率 ≥ 99.5%
- **静默错误率 = 0**（所有错误都被交叉校验捕获，注入测试捕获率 100%）
- 同一文档跑 10 次结果哈希一致

### P3 — xlsx 产出（1–2 周）

**Gate**：Excel / Numbers / Google Sheets 三处打开公式不报错；生成后自检全过。

### P4 — 单文件打包 + 自检报告（1–2 周）

把应用打成单文件 HTML，并实现 self-check report 导出（`docs/06` §4）——这是内部试用能拿到覆盖信号又不接触文档的关键机制。

**Gate**：
- 断网状态下双击 HTML 文件可完整跑通
- 构建产物中第三方网络请求数 = 0（自动化检查）
- self-check report 中不含任何金额、姓名、账号

### P5 — 内部试用（4–8 周）

运营细节见 `docs/08`。核心纪律：**你不接触任何人的文档。**

**前提**：试用者必须是美国纳税人（有 1099-B 才跑得动）。若你所在团队多为非美国纳税人，试用池要在美国团队找，见 `docs/09` §7.6。

试用的目标不是用户量，是两个覆盖信号：

| 指标 | 目标 |
|---|---|
| 覆盖的券商版式数 | ≥ 3 |
| 触发过的失败路径种类 | ≥ 8 |
| 完成全流程并确认结果合理的人数 | ≥ 10 |
| 由试用反馈新增的 golden case（合成重建） | ≥ 5 |

**Gate**：连续 20 次运行无 `InvariantViolation`；所有报告过的失败都能在本地用合成 case 复现。

### 分支点 — 是否对外

P5 结束后做一次显式决策。**对外发布不是默认路径。**

选择对外，则激活 `docs/07` §4 的全部义务清单，其中最重的是 IRC §7216 的适用性分析与同意架构。那部分工作量与 P0–P5 加起来是一个量级的。

选择不对外，项目可以就停在内部工具状态，这是完全合理的终点。

## 内部试用阶段的四条纪律

浓缩版，完整版见 `docs/07` §2 与 `docs/08`：

1. **P-1 的 IP 归属先谈清楚**，在引入任何同事之前
2. **不接触任何人的文档**——同事本地跑，只回传不含数值的自检报告
3. **零出网、零持久化从第一天做**，现在免费，以后是重构
4. **免责与不变量一条不放松**——同事拿输出去报税，算错了没有公司实体挡在中间

`docs/02` §4 的不变量 I5（调整方向只能为负）在内部试用阶段比对外发布时**更**重要，不是更不重要。
