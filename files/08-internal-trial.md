# 08 — 内部试用运营

P4–P5 阶段的操作手册。目标是在**不接触任何人文档**的前提下拿到覆盖信号。

---

## 0. 前提：试用者必须是美国纳税人

工具的输入是 Form 1099-B 与 W-2，只有美国纳税人才有。非美国纳税的同事即使持有同一家公司的 RSU，也跑不动这个工具。

因此试用池必须在美国团队找。若开发者本人是非美国纳税人，还有两个连带后果：

- 你无法作为第一个用户跑通全流程，只能靠自检报告间接观察
- 加上 `docs/07` §2.1 的不接触文档纪律，一次迭代往返从「分钟」变成「天」

对冲手段见 `docs/09` §7.5。这不改变纪律，但要在时间预算里留出余量。

---

## 1. 试用的目标

不是用户量，不是「反响好不好」。是两件具体的事：

1. **券商版式覆盖** — 你只有自己那家的文档，需要知道其他家长什么样
2. **失败路径验证** — `docs/05` 列了 21 条，你需要知道哪些真的会触发、以什么频率

对应的指标见 `README.md` P5。**没有「日活」这类指标**，因为一个报税工具在非报税季本来就没人用，追这个指标会导致错误决策。

---

## 2. 分发

### 2.1 形式

单个 HTML 文件。同事下载后双击，在浏览器里打开，本地运行。

不做托管页面。原因有二：托管意味着有服务端日志、有访问记录、有一个可以被扩散的链接；而单文件可以断网运行，是「文档不出设备」最直接的证明。

### 2.2 渠道

**点对点，不群发。**

- 一对一发送（取决于 P-1 的 IP 归属结论，可能是内部 IM，也可能是私人渠道）
- 不发到任何频道、邮件列表、内部论坛
- 不上传到公开的 GitHub Release 或个人网站

理由见 `docs/07` §4.1：一旦「公开可注册」这条线被越过，州级隐私法与 FTC Act §5 就激活了，而一个公开链接就足以构成越线。

### 2.3 版本管理

每份分发的文件名带版本与构建哈希：`rsu-basis-v0.4.2-a1b2c3d4.html`

同事回报问题时先问版本。没有服务端，你无法推送更新——这是单文件形态的代价，接受它，不要为此引入自动更新（那需要出网）。

---

## 3. 随分发附带的说明

每次分发都附一段文字。以下是模板，可直接用：

> 这是一个还在开发中的工具，用来检查 1099-B 上 RSU 的成本基础是否被低报。
>
> **怎么用**：下载 HTML 文件，双击打开。把你的 1099-B（含后面的 Supplemental Information 部分）和 W-2 拖进去。全部计算在你的浏览器里完成。
>
> **你可以自己验证这一点**：断开网络连接再跑一遍，功能完全正常。这个文件不发送任何数据到任何地方，包括发给我。
>
> **请不要把你的文档发给我。** 我不需要，也不应该拿到。如果你不小心发了，我会立即删除并告诉你。
>
> **重要**：这个工具产出的是工作底稿，不是税务申报表，不构成税务建议。它可能算错。请在提交申报前把结果交给你的会计师复核，不要直接照抄。我对使用结果不承担责任。
>
> **如果你愿意帮忙**：跑完后工具会生成一份自检报告，里面不含任何金额、姓名或账号——你可以自己打开看一遍确认。如果方便，把它发给我，能帮我知道哪些券商版式还没支持。完全自愿。

三个要点缺一不可：**主动拒收文档**、**免责与 CPA 复核**、**自检报告自愿且可自查**。

---

## 4. 反馈处理

### 4.1 收到自检报告

1. 检查报告里确实没有数值（虽然有自动断言，但人工再看一眼）
2. 记录：券商、失败路径 ID、校验编号、差额数量级
3. 若是新券商 → 走 §4.2
4. 若是已支持券商上的失败 → 用合成方式重建场景，加入 golden set（`docs/06` §5）

### 4.2 收到新券商

请对方填 `docs/06` §3.1 的结构描述表。里面没有一个数字，只有表头原文和版式信息。

这足以写出适配器的大部分。剩下的靠对方跑自检报告迭代。

### 4.3 有人直接发来文档

按 §3 说明里的承诺执行：

1. 立即删除（包括 IM 客户端缓存、下载目录、回收站）
2. 告知对方已删除
3. 重申不需要文档，并说明可以怎样帮忙

不要因为「反正都发来了，看一眼没关系」而破例。这条线一旦破，`docs/07` §4 的第二行就激活了。

---

## 5. 不要做的事

| 不要 | 原因 |
|---|---|
| 收集文档 | `docs/07` §4 第二行 |
| 群发或公开链接 | `docs/07` §4 第四行 |
| 收任何费用，哪怕象征性 | §7216 preparer 认定 |
| 加自动更新或崩溃上报 | 需要出网，破坏 R8 |
| 加使用统计 | 同上 |
| 说「这个算得准」「你可以直接用」 | `docs/05` §6 |
| 帮同事解读他的具体税务情况 | 那是税务建议 |
| 为了让某个人跑通而临时放宽不变量 | `docs/02` §6 |

最后一条最容易犯。同事说「它卡住了不让我继续」，你想帮他，于是想加个「忽略并继续」的开关——**不要。** 卡住是设计意图。正确的回应是搞清楚为什么卡住，然后修 bug 或承认这个 case 超出范围。

---

## 6. 扩大范围时的检查

每次要多加人、换分发方式、或有人提出新用法时，走一遍：

- [ ] 重读 `docs/07` §4 的触发表，确认没有越线
- [ ] 若越线，先停下，评估激活了哪些义务
- [ ] 确认 P-1 的 IP 归属结论仍然覆盖新范围
- [ ] 确认分发说明（§3）随最新版本一起发出
- [ ] 确认当前版本的不变量与免责都没有被削弱

范围扩大通常是渐进无感的，而义务的激活是阶跃的。这个检查表的作用就是把渐进变成有意识的决策点。

---

## 7. 试用结束

P5 的 gate 达成后（`README.md`），做一次显式决策：

- **停在内部工具**：完全合理的终点。把文档归档，代码保留
- **对外**：进入 `docs/07` §5 的清单，第一件事是 §7216 法律意见

**不做决策 = 默认继续内部试用**，而不是默认对外。这个默认值是刻意设的。
