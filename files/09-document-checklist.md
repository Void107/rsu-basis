# 09 — 原料清单

P0 阶段需要的文档。**全部是你自己的**——不接收他人文档的纪律从第一天生效（`docs/07` §2.1）。

目标是凑齐最近 3 个税年。凑不齐 3 年也能开工，但 golden set 的覆盖会窄一些。

---

## 1. 为什么现在就要下载

三个都是真实会发生的坑：

- **券商对历史税表的保留期有限**，有些只留 3–7 年
- **换过工作的话，前雇主的股权平台账号可能已被降权或关闭**。这类账号通常在离职后一段时间内还能登录下载，之后就不行了
- **修正版 1099-B 在 2 月底到 3 月发出**。如果你手上是早期版本，数字可能已经变了

拖到 P1 才发现下不到，整个 golden set 计划要改。

---

## 2. 从券商 / 股权平台

### 2.1 Form 1099-B（Consolidated 1099）

正式税表。RSU 的成本基础在这上面是错的（$0 或空白），但你需要它作为「照抄」的来源——`docs/01` §6 要求 proceeds 和 reported basis 必须原样保留。

### 2.2 补充信息表 ← 最关键的一份

**正确的数字全在这里，而它不发给 IRS。**

命名各家不同，找这几个词的组合：

- Supplemental Information
- Stock Plan Supplemental Information
- Supplemental Stock Plan Lot Detail
- Cost Basis Supplemental / Adjusted Cost Basis

**位置**：多数券商把它放在 1099-B 那个 PDF 的**后半部分**，常常在第 40 页之后。有的券商是单独一个下载项。

如果在合并 PDF 里找不到，去券商网站的 tax documents 区域看有没有单独的下载条目。

### 2.3 Release / Vest 确认单

每次 vest 一份，显示：vest 股数、采用的 FMV、代扣股数。名称可能是 Release Confirmation、Award Detail、Vest Confirmation。

用途：当补充表缺字段时的备份来源。

### 2.4 交易确认单 / 历史交易记录

open-market 卖出的成交价与时间。补充表通常也有，但确认单更权威（含费用明细）。

### 2.5 Form 3922（如果有 ESPP）

V1 范围外（`docs/01` §1），但**下载并保留**——它是 V1.2 的原料，而且以后不一定还能下到。

---

## 3. 从工资 / HR 系统

### 3.1 W-2

看 **Box 14** 有没有 RSU 那一行。这是 `docs/01` §3.3 的 `W2Anchor.rsuIncomeReported`，也是校验 C5 的锚点。

Box 14 的标签各公司不统一（`RSU`、`RSU INC`、`STOCK`、`EQTY`……），找数量级对得上的那一行。

### 3.2 每个 vest 日的工资单 ← 被低估的一份

这是整份清单里最容易被跳过、但价值最高的一份。

vest 通常在工资单上作为一个 earnings 行项目出现，**给你一个独立于券商的 FMV 数字**。这正是校验 C2（乘积一致）需要的独立来源——如果只有券商一个来源，C2 就退化成自己验证自己。

去工资系统下载 vest 当期（不一定是当天，可能是下一个发薪周期）的工资单。

### 3.3 年度工资汇总（如果有）

有的公司提供 year-end payroll summary，会把 RSU 收入单列出来。比 Box 14 更清楚。

---

## 4. 下载后的五分钟检查 ← 只有你能做

这一步验证的是整个项目最底层的假设。**在写任何代码之前做。**

打开补充信息表那份 PDF，逐条确认：

| # | 检查 | 不通过怎么办 |
|---|---|---|
| 1 | **能否用鼠标选中表格里的文字？** | 选不中 = 扫描图 = `docs/03` 的 pdfjs 方案不成立，架构要重想 |
| 2 | 有没有逐 lot 的行（每行一次 vest）？ | 只有汇总 → 这家券商不可用，见 §5 |
| 3 | 每行是否包含：取得日期、股数、ordinary income、调整后成本？ | 缺字段 → 用 §2.3 的确认单补 |
| 4 | **有没有印刷的合计行？** | 没有 → 这家券商必须设计替代锚点，否则不支持（`docs/03` §4） |
| 5 | 「调整后成本」那列是每股还是总额？ | 用 `总额 ÷ 股数` 试算判断 |
| 6 | W-2 Box 14 的 RSU 金额，和补充表逐行相加是否接近？ | 差很多 → 可能漏了某次 vest，或 Box 14 含其他股权收入 |

第 1 和第 4 条是 P0 的真正 gate。**其余都可以将就，这两条不行。**

### 4.1 把检查结果记下来

按 `docs/03` §3 的格式，直接写进那家券商的适配器文件顶部注释：

```
版本样本：2024 tax year
补充表位置：第 47 页起，标题原文 "Supplemental Information"
必需列的列头原文（照抄，不要改写）：
  vest date          → "Date Acquired"
  调整后成本          → "Adjusted Cost or Other Basis"  [每股 / 总额：____]
  ordinary income    → "Ordinary Income Reported"
  股数               → "Quantity"
合计锚点：有，第 51 页底部 "Total"
已知坑：
  - ...
```

**列头必须照抄原文，不要顺手改写成更规范的说法。** 适配器要按原文做字符串匹配。

---

## 5. 如果你自己那家券商不可用

比如是扫描图，或者没有逐 lot 明细。

**不要硬上 OCR**，也不要立刻去找同事要别家的文档（那会越过 `docs/07` §4 的第二条线）。

正确的做法：`docs/10` 的合成案例已经把引擎和 xlsx 两层的开发解锁了——**P1 和 P3 完全不依赖真实文档**。你可以先做这两层，把提取层（P2）推后，等有别家券商的结构描述表再说。

这个顺序反而更好：引擎和输出层做扎实了，提取层只是往里灌数据。

---

## 6. 存放

按 `docs/07` §2.4：

- 放在全盘加密的磁盘上
- 不进任何仓库，不进任何云同步目录
- `.gitignore` 里加一条，防止手滑

含真实数值的文档**永远不进 `test/golden/`**。golden set 只放合成案例和你手工誊抄出来的脱敏数值（见 `docs/10` §7）。

---

## 7. 如果你不是美国纳税人

本节适用于：在美国公司的全球股权计划里持有 RSU，但在美国境外纳税；或完全没有 RSU。

### 7.1 先把问题拆开

「没有美国报税经验」影响的不是原料清单本身，而是 **P0 的 gate 能不能达成**。把假设拆成两组：

| 假设 | 能否自行验证 | 靠什么 |
|---|---|---|
| lot 级数据存在、字段齐全 | ✅ | 你自己的券商门户 |
| 每股 vs 总额、FMV 口径 | ✅ | 同上 |
| 补充表在 PDF 里的版式与可提取性 | ❌ | 公开样本 + 美国同事的结构描述表 |
| **有无印刷合计行**（C1 锚点） | ❌ | 同上 |

后两条是 P2 的核心风险。**承认这个缺口，不要假装绕过去。**

### 7.2 你可能已经有的

如果 RSU 通过美国券商（E*TRADE / Schwab / Fidelity / Morgan Stanley / Shareworks）发放，去股权平台找：

- **Vest / Release 确认单** — 每次 vest 一份，含股数、采用的 FMV、代扣股数
- **交易历史 / 成交确认单**
- **lot 级明细报表** — 关键。很多平台的 Equity Award Center 提供 CSV 导出（名称类似 Gains & Losses、Cost Basis、Lot Details）

这些是**账户数据，不是美国税表**，通常与你的税务居民身份无关。它们足以验证 §7.1 表格的前两行。

你不会有的：Form 1099-B、Supplemental Information、W-2。

### 7.3 替代原料：公开样本（主力）

**完整清单已整理在 `docs/11`**，含实际验证过的链接。三个梯队：

1. **券商教育材料** — 版式来源。Fidelity 的 Stock Plan Services 报税指南最完整，含 W-2、1099-B、**Supplemental Information**、Form 8949、Schedule D 的全套样本表格
2. **IRS 官方表格与 instructions** — 权威的字段定义与 box 编号
3. **美国同事的结构描述表**（`docs/06` §3.1）— 唯一能拿到真实世界信息的渠道

公开样本给不了的：第 47 页的实际位置、跨页表格断行、修正版标记、多 CUSIP 混排、扫描件、**有无印刷合计行**。这些只能靠第 3 项。

### 7.4 P0 的 gate 改写

原 gate（「至少 1 家券商确认可提取全部必需字段且有合计锚点」）无法达成。改为：

**Gate A — 数据存在性（你自己做）**
- [ ] 在券商门户拿到 lot 级明细，确认包含：vest 日期、股数、每股 FMV 或调整后成本、代扣股数
- [ ] 确认「调整后成本」是每股还是总额
- [ ] 确认 FMV 口径（收盘价 / 高低均价 / 前一日收盘）

**Gate B — 版式可行性（靠公开样本）**
- [ ] 至少拿到 1 份含补充表样本的券商报税指南
- [ ] 按 `docs/03` §3 的格式记录列头原文
- [ ] 确认样本中存在合计行

**Gate C — 真实世界验证（推迟到 P5）**
- [ ] 至少 1 位美国同事回填结构描述表，确认样本版式与实际一致
- [ ] 至少 1 份自检报告显示 C1 校验通过

**Gate C 无法在 P5 之前达成。** 这意味着 P2 的提取层在很长一段时间里是「按样本写、未经真实验证」的状态。

### 7.5 对冲

三条，都不需要真实文档：

1. **把 P2 往后放。** P1（引擎）和 P3（xlsx）完全不依赖真实文档——`test/golden/` 里的合成 case 已经解锁了这两层。先做它们，提取层最后做。这个顺序反而更健康。

2. **加厚交叉校验。** 正因为你无法预先知道版式有多脏，`docs/03` §4 的 C1–C7 从「安全网」升级为「主要防线」。宁可多阻断，不可静默通过。

3. **合成集加倍。** `docs/06` §1 原本设定合成集 15–20 组；在这个情形下按 25–30 组做，把 `docs/10` §7.1 的边界条件全部覆盖。合成集是你唯一完全可控的验证手段。

### 7.6 对内部试用的连带影响

`docs/08` 有个未写明的前提：**试用者必须是美国纳税人。** 和你情况相同的同事没有 1099-B，跑不了这个工具。

因此：
- 试用池要在美国团队找，这会影响 `docs/08` §2.2 的分发渠道选择
- 你自己无法作为第一个用户跑通全流程——**这是这个项目最大的非技术风险**
- `docs/07` §2.1 的不接触文档纪律意味着你只能靠结构描述表和自检报告迭代，往返周期从「分钟」变成「天」

### 7.7 一个需要你自己判断的问题

「自己就是用户」是这个想法最初的吸引力来源之一：你能亲身体会那个「我多缴了一万八」的时刻，也能最快验证。失去它之后，产品直觉要靠 `docs/10` 的手算和美国同事的反馈来补，两者都更慢、更间接。

这不构成放弃的理由——很多人做着自己不用的产品。但它应该改变你对时间预算的预期，也让 `docs/10` 的手算从「建议」变成**必做**：那会是你唯一的第一手直觉来源。

**另一个方向**（仅作为选项列出，不是建议）：你所在辖区的员工持有美股 RSU 也有自己的税务复杂度——归属时的工资薪金所得、卖出时的财产转让所得、境外所得申报。那是一个你天然有直觉的问题，但市场小得多、规则差异也大，属于完全不同的产品判断。
