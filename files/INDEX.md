## 关键决策记录

按重要性排序。每条记录**结论 + 理由**，理由比结论更重要——改动前先确认理由是否仍成立。

### D1 — LLM 只做提取，不做算术
所有数值计算由确定性代码完成，LLM 只做非结构化 → 结构化。
**理由**：这个品类的错误是静默的、单向的。模型幻觉在税务场景不可接受，只能靠架构隔离，不能靠 prompt 约束。
→ `CLAUDE.md` R3、R4

### D2 — 缺数据就停，绝不内插
schema 中未确证的字段为 `null`，引擎遇 `null` 抛错。
**理由**：模型天生倾向填补空缺。「请不要猜」拦不住，只有让它没有机会经手才行。
→ `CLAUDE.md` R2

### D3 — 调整方向只能为负（不变量 I5）
任何一条调整让应税所得增加，一律硬阻断，不可配置关闭。
**理由**：产品的全部价值是调高基础、降低应税所得。方向反转会让用户少缴税、收 IRS 通知、承担罚息——比不用这个工具更糟。
→ `docs/02` §4

### D4 — 先设计失败路径，再设计成功路径
**理由**：happy path 最容易，价值和风险全在边缘。
→ `docs/05`

### D5 — 独立引擎，本地应用

当前提供自包含 HTML；核心计算不依赖组织账号、Agent 平台或表格编辑器。任何用户都能体验合成案例，真实计算仍受适用范围和验证状态约束。未来宿主适配不应改变规则和检查要求。

### D6 — 本地数据处理

不建立业务网络请求、遥测或浏览器存储通路；保留 CSP 与自动化检查。发布前还需要真实浏览器验证。导出底稿含用户数据，不能把隐藏台账视为脱敏。
→ `CLAUDE.md` R8

### D7 — 不接收用户真实材料

用户在自己的设备上处理资料，自愿提供无敏感信息的诊断报告。维护者使用公开样本与合成案例复现问题。
→ `CLAUDE.md` R9、`06-eval-harness.md` §2

### D8 — 正式发布需要验收

预览不等于正式可用。是否公开仓库、发布构建或提供收费服务，由维护者依据真实能力和发布要求决定；不限制用户的工作单位或邮箱域名。
→ `07-obligations.md` §4、§5

### D9 — golden set 主力是合成集，不是真实文档
**理由**：D7 排除了他人文档；合成集还能精确制造边界条件，真实文档只能碰运气。
→ `docs/06` §1

### D10 — 期望值必须由独立脚本验算
不得用工具自身输出当 expected。
**理由**：那样只能锁住「行为没变」，锁不住「行为是对的」。`synthetic-002` 的一处错误就是靠 `verify.py` 才发现的。
→ `docs/06` §7、§10

### D11 — xlsx 用活公式，且生成后自检
**理由**：公式字符串靠拼接，最常见的 bug 是行号偏移一行——不抛异常，只产出一份看起来正常但数字全错的表。自检是唯一抓法。
→ `docs/04` §7

### D12 — 预览不启用 LLM 回退

当前没有模型调用。未来如需云端提取，应先定义数据接收方、授权与保留规则，独立验证后再启用，不能沿用本地模式的隐私承诺。
→ `07-obligations.md` §3.1

### D13 — 调整后基础用加法式定义
`adjustedBasis = 归属时普通所得 + 1099-B 上报的基础`，而非 `股数 × vest FMV`。
**理由**：来自 Fidelity 官方定义。1099-B 报 $0 时两者相同，报非零时只有加法式对。
→ `docs/02` §2.4、`docs/11` §5.1

### D14 — 8949 有两种输出形态
由 1099-B Box 12（基础是否报送 IRS）决定，不是由 `covered` 决定。
**理由**：已报送 → Box A/D + 代码 B + (g) 列调整额；未报送 → Box B/E，正确基础直接进 (e) 列，无代码。**这是两条不同路径**，不是同一套行加标记。
→ `docs/01` §6.1、`docs/11` §5.2

### D15 — 新增 C9「逐字符回比」，立即生效
`docs/03` §4 的七条校验全部锚在补充表/W-2 侧（lot 字段），1099-B 侧只有 C6（长短期）。
`docs/06` §8 的注入测试暴露出三类扰动**静默通过**：`proceeds` 读错一位、`reportedBasis`
读错一位、`saleDate` 错一天且未跨越持有期边界（C6 只在 term 翻转时才报警）。

C9 要求：任何进入 schema 的字段，其归一后的值必须能由 `SourceRef.rawText` **逐字符复现**
（`parse(rawText)` 存在且等于该值），且 `method` 只能是 `rule` / `manual`——推断值无法回比，
等于绕过本条。

**理由**：这不是跨源锚定（那是 C1/C8），但它挡住**解析层读错**，而解析层读错正是注入测试
模拟的东西、也是提取层最主要的错误来源。它不依赖 Gate C，今天就能生效——在拿到 C8 之前，
`reportedBasis` 不接受「暂时没有锚点」，由 C9 提供立即可用的下界防护。
→ `src/extraction/c9.ts`，失败路径 **F22**

### D16 — 新增 C8「1099-B 合计锚定」，标记为 pending
对称于 C1，但锚在 1099-B 主表：逐笔 `proceeds`（Box 1d）/ `reportedBasis`（Box 1e）之和
== 表上印刷合计。

**理由**：C9 只能证明「我们没读错文档」，不能证明「没漏读整行」。跨源合计锚定是唯一能抓
漏行的机制——C1 对补充表如此，1099-B 侧同理。

**为何 pending**：1099-B 主表是否有印刷合计/小计行无法从公开样本确认（`docs/11` §3 把
「有没有印刷合计行」列为公开样本**不能**提供的项）。因此 `hasPrintedTotal1099B` 三态标
`unknown`，**运行时硬阻断**而非静默跳过；完整逻辑已实现并用合成 fixture 双分支测试。
与 Fidelity 补充表合计行是**同一个待办**，一起等结构描述表（`docs/06` §3.1 / Gate C）回填，
届时改一行即可。
→ `src/extraction/c8.ts`，失败路径 **F23**

> C8/C9 与 F22/F23 是本仓库对 `docs/03` §4、`docs/05` 的增补，尚未回写进那两份规格文档。

## 当前状态

已实现确定性引擎、提取基础设施、XLSX 生成与回读自检、合成案例 UI，以及四组合成 golden case。现有 CI 已通过，但不代表全部领域规则和真实文件路径已验证。

当前没有任何券商版式通过完整启用验收。真实 PDF 到最终底稿仍未形成可供正式使用的闭环。界面与文档标记为独立预览版，不需要组织身份。

## 已知缺口

- 真实版式、字段粒度、合计锚点与浏览器 PDF worker 需要验证。
- 输入范围、匹配时序、基础组成、跨年口径及舍入边界需要进一步修复与专业复核。
- Agent 工具接口和表格编辑器适配尚未实现；核心引擎没有这些宿主依赖。
- 正式分发、云处理或收费前按 `07-obligations.md` 检查实际方案。
